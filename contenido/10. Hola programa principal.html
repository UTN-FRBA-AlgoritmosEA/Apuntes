Vamos parte por parte:

  • #include <iostream> trae la biblioteca de entrada y salida (iostream = input/output stream), que es donde están definidos cout y cin. Sin ese #include, el compilador no sabría qué son y daría error.
  • int main() es el punto de entrada del programa: cuando lo ejecutamos, la computadora empieza a correr las instrucciones que están dentro de main. Todo programa de C++ tiene exactamente uno. Es la contraparte del programa principal del diagrama: las marcas de inicio (I) y fin (F) son, justamente, la apertura y el cierre del main.
  • return 0; es lo último que hace el main: le devuelve un número al sistema operativo para avisar cómo salió todo. Por convención, 0 significa «terminó bien, sin errores»; un número distinto avisaría que algo falló.

El main es, en realidad, una función (algo que veremos más adelante); por ahora alcanza con saber que el int de adelante y el return 0 del final van de la mano.

Un detalle más: escribimos std::cout y std::endl, con ese std:: adelante. Es porque cout, cin y endl viven dentro de un espacio de nombres llamado std (de standard, la biblioteca estándar), y el :: significa «el cout que está dentro de std».

Evitando el std:: con using namespace

Poner std:: delante de cada nombre se vuelve tedioso enseguida. Para evitarlo, agregamos cerca del principio la línea using namespace std;, que le dice al compilador: «si ves un nombre suelto, buscalo también dentro de std». Con eso podemos escribir cout y endl a secas:

¿Y qué es un espacio de nombres (namespace)? Es una forma de agrupar nombres para que no choquen entre sí: dos bibliotecas distintas podrían definir cada una algo llamado max, y el namespace permite distinguir uno de otro. La biblioteca estándar de C++ mete todo lo suyo en el namespace std. No vamos a ahondar más; por ahora alcanza con reconocerlo y saber por qué aparece.

De hecho, es lo que veníamos asumiendo: en los ejemplos anteriores escribimos cout y cin a secas dando por sentado este using namespace std;.

Un dato: los namespaces son una característica propia de C++; en C no existen. Por eso, en C los nombres de las funciones de una biblioteca suelen llevar prefijos o sufijos para evitar que choquen entre sí —una especie de namespace hecho a mano.

Con esto ya sabemos armar un programa entero: los #include que necesitemos arriba, el main con nuestro algoritmo adentro y el return 0 al final. De acá en más, cuando mostremos un programa completo, va a tener esta forma.

Luz, cámara, acción

Ahora veamos el programa en ejecución.

Si bien los diagramas no compilan podemos hacer un seguimiento a mano de la ejecución para verlo andar. A continuación está la ejecución del diagrama paso a paso: usá los controles para avanzar. En cada paso se resalta la instrucción que se está ejecutando, la consola muestra lo que el programa escribe y pide, y más abajo se ven los valores de las variables en cada momento. Cuando dicen «desconocido» es porque no sabemos qué valor tienen ya que nunca les asignamos un valor, pero ya ocupan un espacio en memoria y por lo tanto ya tienen un valor residual de lo que había en ese lugar de memoria antes de asignarse a nuestro programa. Usar una variable con valor residual es un error de programación y por tanto los compiladores modernos ayudan a que eso no ocurra advirtiendo de ese error cuando existe esa posibilidad.
